# Premarket Alert (日本株 寄り付き・トレンド監視システム)

毎朝、東証の全上場銘柄から強いトレンドを持つ銘柄を抽出し、寄り付き直後に「前日比で上昇し、かつ出来高が平常時より多い」銘柄をSlackに自動通知するシステムです。
毎朝、該当がなくても「何銘柄チェックして何件取得に失敗したか」の1行サマリーが届きます。

## ⚙️ システムの流れ（完全自動）

1. **07:55 - Macが自動起床**
   - スリープ状態から自動的に復帰します。
2. **08:00 - ウォッチリストの自動更新** (`update_watchlist.py`)
   - 東証の全銘柄データを取得し、厳しい条件（流動性・トレンド・高値圏）でスクリーニング。
   - 合格した優良銘柄だけを `watchlist.txt` に書き出します。
   - 取得に成功した銘柄が半分未満なら、前日のリストを残したまま異常終了します(サマリーに「リストが古い」と出ます)。
   - 9:45 まで `caffeinate` で Mac をスリープさせないようにします。
3. **09:25 - 寄り付き直後の急騰検知** (`premarket_alert.py`)
   - `watchlist.txt` の銘柄群に対し、当日の寄り付き状況を確認。
   - 条件を満たした銘柄と、毎朝の1行サマリーをSlackへ通知します。
   - スリープ復帰などで **9:40 を過ぎて起動した場合は判定せず**、「スキップした」とだけ通知します。

---

## 🔍 売買手法とフィルター条件

### 手法の考え方
**「中長期で上昇トレンドにある流動性の高い銘柄が、寄り付き直後に出来高を伴って上放れた瞬間」を捉えるモメンタム(順張り)戦略**です。

1. **8:00 の事前スクリーニング**:「上がりやすい土台がある銘柄」に絞ります(日足ベース)。
2. **9:25 の当日判定**:その中から「今日まさに資金が流入している銘柄」を検出します(分足ベース)。

判定に使うデータはすべて **株価と出来高のみ**(テクニカル)です。任意で、前夜に自分で調べた「材料あり銘柄」を組み合わせることもできます(下記「材料フィルター」)。

> [!IMPORTANT]
> **ファンダメンタル条件は現在1つも実装していません。** 業績・PER/PBR・時価総額・決算日などは見ていません。
> 時価総額のフィルターは、全銘柄分を毎日取得する負荷が高いため実装を見送り、代わりに「売買代金5億円以上・株価250円以上」で小型株や低位株を除外しています。

### ステップ1:ウォッチリスト抽出(8:00 / `update_watchlist.py`)
対象は東証の全上場銘柄のうち「内国株式」です(ETF・REIT・ETN などは除外)。前営業日までの日足(過去6か月)で判定し、**以下をすべて満たす銘柄**を `watchlist.txt` に書き出します。

| 分類 | 条件 | しきい値 | 狙い |
|---|---|---|---|
| 流動性 | 25日平均売買代金(終値×出来高) | **5億円以上** | 板が薄く、少額の買いで値が跳ねる銘柄を除外 |
| 株価水準 | 直近終値 | **250円以上** | 超低位株(ボロ株)を除外 |
| トレンド | (終値 > 25日移動平均 **かつ** 25日線が上向き)**または**(終値 > 75日移動平均 **かつ** 75日線が上向き) | — | 下降トレンド中の一時的な反発(ダマシ)を除外 |
| 高値圏 | 直近終値が、過去60日の最高終値から何%下にあるか | **10%以内** | レンジ上限(抵抗線)付近にあり、ブレイクを狙える位置 |

- 移動平均の「上向き」は、**当日値が前日値より大きいか**だけで判定しています。
- 75日線を計算するため、上場から80営業日未満の銘柄は対象外になります。

### ステップ2:寄り付き直後のアラート判定(9:25 / `premarket_alert.py`)
ウォッチリストの各銘柄について、直近8日分の1分足と過去1か月の日足を `yf.download` でまとめて取得して判定します。**以下をすべて満たす銘柄**を Slack に通知します。判定ロジックは `strategy.py` にあり、バックテストと共通です。

| # | 分類 | 条件 | 既定値 | 環境変数 | 狙い |
|---|---|---|---|---|---|
| 1 | 前日の過熱 | 前日の騰落率 | **+5%未満** | `PREV_DAY_MAX_RETURN` | 前日に急騰した銘柄の翌日の利確売りを避ける |
| 2 | 前日の過熱 | 前日出来高 ÷ その前5日の平均出来高(前日自身は含めない) | **2倍未満** | `PREV_DAY_MAX_VOL_RATIO` | 同上(材料出尽くしを避ける) |
| 3 | 前日比 | 現在値の前日終値比 | **+3%〜+10%** | `MIN_CHANGE` / `MAX_CHANGE` | 上昇は必須、ただしストップ高付近の上がりすぎは除外 |
| 4 | 出来高 | 時刻別RVOL(下記) | **1.5倍以上** | `RVOL_THRESHOLD` | 資金流入の強さ(相対出来高) |
| 5 | ローソク足 | 現在値 ≥ 当日の始値(日足のOpen)(陽線) | — | — | 寄り天(高く始まってすぐ売られる)を除外 |
| 6 | 高値維持 | 当日高値からの下落率 | **1%以内** | `CLOSE_TO_HIGH_THRESHOLD` | 上ヒゲをつけて失速した銘柄を除外 |

- 条件3は「寄りでのギャップ」ではなく**現在値の前日比**です。寄りでギャップしていなくても、寄った後に3%上がれば通ります。通知には参考として寄りギャップ(始値の前日比)も出します。
- 旧名の環境変数 `GAP_THRESHOLD` / `MAX_GAP_THRESHOLD` / `TARGET_DAILY_RATIO` も引き続き読み込みます(ただし `TARGET_DAILY_RATIO` は意味が「時刻別RVOLの倍率」に変わっています)。

**時刻別RVOLの計算方法(条件4)**
- 出来高は寄り付き直後と大引けに集中する(U字型)ため、1日の出来高を時間で按分すると朝の要求ラインが甘くなりすぎます。
- そこで「**当日の、最後に見えている足の時刻までの累積出来高**」を「**過去5営業日の、同じ時刻までの累積出来高の平均**」で割ります。
- 時刻は `datetime.now()` ではなく**最後の足の時刻**を使うので、データの遅延があってもズレません。
- yfinance の1分足は日によって 9:00〜9:04 の足があったりなかったりするため、比較は **9:05 以降の足だけ**で行います(下記「既知の制約」)。そのため 9:05 以降の足がまだ見えていなければ「データ不足」として判定しません。

**毎朝の1行サマリー**
```
📋 10/20 09:25 [JP] 321銘柄チェック / 取得失敗 0 / 当日データなし 0 / データ不足 0 / 判定 321 / 該当 1 | データ時刻 09:05 (遅れ20分) | リスト更新 2026-10-20 08:09:12 (取得 3702/3702)
```
次のどれかに当てはまると ⚠️ になり、理由が2行目に出ます:取得失敗が1割超 / 全銘柄で当日データなし(休場日か取得失敗) / データの遅れが30分超 / ウォッチリストが今日更新されていない。

### 材料フィルター(任意 / `catalysts.csv` + `CATALYST_MODE`)
テクニカル条件だけだとダマシのシグナルが多いので、**前夜に PTS や株探のニュースで「材料がある」と判断した銘柄**を手で記録しておき、9:25 の判定と組み合わせられます。材料の判断そのものは自動化しておらず、記録は手作業です。

**ファイルの書き方(`catalysts.csv`)**
`catalysts.example.csv` をコピーして、毎晩1行1銘柄で書き足していきます。過去の行は消さずに残してください(バックテストで使います)。

```csv
date,code,memo
2026-10-20,7203,上方修正 (PTS +4%)
2026-10-20,6758,自社株買い 発行済の3%
2026-10-21,,該当なし
```

| 列 | 内容 |
|---|---|
| `date` | その銘柄を狙う**取引日**(前夜に書くなら翌営業日の日付)。`2026-10-20` / `2026/10/20` のどちらでも可 |
| `code` | 銘柄コード(`7203` / `7203.T` のどちらでも可)。**空欄にすると「その日は調べたが該当なし」**の印になります |
| `memo` | 材料のメモ(省略可)。Slack の通知に表示されます。カンマを含んでもかまいません |

- `#` で始まる行・空行・ヘッダー行は無視します。Excel や Numbers で編集しても、テキストエディタで書き足しても構いません。
- `catalysts.csv` は個人の売買メモなので `.gitignore` に入れてあります(リポジトリには例の `catalysts.example.csv` だけが入ります)。

**モード(環境変数 `CATALYST_MODE`、`secrets.env` に書けば毎朝の自動実行に反映されます)**

| 値 | 動き |
|---|---|
| `off`(既定) | 材料ファイルを読まない。今までどおりテクニカル条件だけで通知 |
| `tag` | テクニカル条件で通知するのは今までどおり。そのうち材料銘柄には 📰 とメモを付ける |
| `only` | テクニカル条件を満たし、**かつ**その日の材料銘柄に入っているものだけ通知(サマリーには「テクニカルのみ」の件数も出ます) |

- ファイルの場所は `CATALYST_FILE` で変えられます(既定はこのフォルダの `catalysts.csv`)。
- テクニカルの判定対象はこれまでどおり `watchlist.txt` の銘柄だけです。**材料銘柄でもウォッチリストに入っていなければ判定されません**(サマリーに「リスト外」として表示されます)。
- `tag` / `only` のとき、毎朝の1行サマリーの末尾に `材料[only] 2銘柄` のように表示されます。ファイルがない、または今日の日付の行が1行もないときは ⚠️ になります(該当なしの日は `code` 空欄の行を書いておけば ⚠️ になりません)。

---

### 使っているテクニカル指標の一覧

| 指標 | どこで使うか | 用途 |
|---|---|---|
| 単純移動平均(SMA 25日・75日)とその傾き | 抽出 | 中期トレンドの方向 |
| 60日高値との距離 | 抽出 | 高値圏・ブレイク候補の判定 |
| 平均売買代金(25日) | 抽出 | 流動性 |
| 前日比(現在値 ÷ 前日終値) | 判定 | 当日の上昇 |
| 時刻別相対出来高(RVOL) | 判定 | 資金流入の強さ |
| 始値との比較(陽線/陰線) | 判定 | 寄り付き後の値動きの方向 |
| 当日高値からの下落率 | 判定 | 勢いが続いているか |
| 前日の騰落率・前日の出来高倍率 | 判定 | 過熱・材料出尽くしの除外 |

### 既知の制約・注意点
- **データの遅延(一番大きな問題)**:Yahoo Finance の日本株データは約20分遅れます。9:25 に実行しても、実際に見ているのは 9:05 前後の値動きです。寄り付き直後のモメンタムは最初の数分〜十数分が勝負なので、通知を見て発注する頃には動きの大半が終わっている可能性があります。無料のままでは解消できません(解消するにはリアルタイムの板情報が取れる証券会社のAPIなどが必要です)。バックテストでは「9:05 までのデータで判定し、9:27 に発注」として、この遅延を織り込んでいます。
- **1分足の寄り直後が欠けている**:yfinance の日本株1分足は、ほとんどの日で 9:04〜9:05 の足から始まり、寄り付きの板寄せ出来高も入っていません。9:25 実行(=9:05 までのデータ)だと、判定に使える足は1〜2本しかありません。始値は日足の Open を使っています。
- **yfinance は非公式 API**:仕様変更や取得制限で、データが取れなくなることがあります。
- **「高値」は終値ベース**:ステップ1の60日高値は、日中の高値ではなく終値の最高値です。
- **傾きの判定が粗い**:移動平均の上向きは前日比だけで見ているため、横ばい付近ではノイズで判定が入れ替わります。
- **売買判断は自己責任で**:このシステムは通知だけを行い、売買の推奨ではありません。

### バックテスト(`backtest.py`)
銘柄や日付を手で選ばず、**取得できる期間の全営業日 × 全銘柄にアラート条件を機械的に当てはめて**成績を出します。判定には `premarket_alert.py` と同じ `strategy.py` の関数を使います。

| 項目 | 内容 | オプション(既定値) |
|---|---|---|
| ウォッチリスト | 各日の前営業日までの日足で、ステップ1の条件をその時点で判定し直す | `--universe watchlist` / `jpx` |
| 見えているデータ | 実行時刻 − 遅延 までの1分足だけで判定 | `--run-time 09:25` `--delay 20` |
| エントリー | 実行時刻 + 反応時間 の1分足の始値 + スリッページ | `--reaction 2` `--slippage 0.1`(片道%) |
| 決済 | 利確 / 損切(同じ足で両方触れたら損切優先・窓を開けたら始値で約定)/ 時間切れ / 大引け | `--tp 1.5` `--sl 1.5` `--hold-minutes`(なし=大引け) |
| 手数料 | 片道%で往復分を差し引き | `--fee 0` |
| 材料 | 材料ファイルを読み、材料あり/なしに分けて集計(下記) | `--catalysts catalysts.csv` |

比較のため「**その日のウォッチリスト全銘柄を同じルールで買った場合**」(ベースライン)も表示します。アラート条件に優位性があるなら、ベースラインより成績が良いはずです。

```bash
/Users/msngkntr/.venv/bin/python backtest.py                    # 今の運用 (9:25実行)
/Users/msngkntr/.venv/bin/python backtest.py --run-time 09:40   # 実行を遅らせてデータが揃うのを待った場合
/Users/msngkntr/.venv/bin/python backtest.py --universe jpx --csv trades.csv
/Users/msngkntr/.venv/bin/python backtest.py --run-time 09:40 --catalysts catalysts.csv
```

`--catalysts` を付けると、ふだんの2つの集計に加えて次の3つを同じ形式で出します。シグナル一覧にも「材料」の列が付きます。

- **アラート条件 × 材料あり**:`CATALYST_MODE=only` で運用した場合の成績
- **アラート条件 × 材料なし**:材料フィルターで捨てることになるシグナルの成績
- **ベースライン × 材料あり**:材料銘柄をテクニカル条件なしで全部買った場合(材料だけで優位性があるかの目安)

集計は**材料ファイルに1行でも記録がある日だけ**で行います。記録のない日は「材料なし」ではなく「調べていない日」なので、どちらにも入れません。該当なしの日も `code` 空欄の行を書いておくと、その日のシグナルは「材料なし」として集計されます。

> [!NOTE]
> yfinance の1分足は直近30日分しか取れないため、バックテストで使えるのは**直近30日以内に記録した材料だけ**です。今日から記録を始めた場合、比較に意味が出てくるのは記録が数週間分たまってからです(それでも十数営業日なので目安です)。30日より前の記録はファイルに残しておいても集計には使われません。

> [!WARNING]
> - yfinance の1分足は**直近30日分しか取れない**ため、検証できるのは十数営業日です。統計的に意味のある結論を出すには、日々の結果をためていくか、長期の分足データが必要です。
> - 既定の `--universe watchlist` は「今日のリストに残っている銘柄」だけが対象なので、途中で条件から外れた銘柄が抜けます(生存バイアス)。厳密に見るなら `--universe jpx`(全銘柄の日足を取るので時間がかかります)。

*(※ しきい値は環境変数、または `premarket_alert.py` / `update_watchlist.py` の上部の定数で変更できます)*

## 🚀 セットアップと手動コマンド

既に設定は完了していますが、設定を変更したり手動でテストしたい場合は以下のコマンドを利用してください。

### 1. ウォッチリスト更新の手動実行
銘柄リストの抽出を今すぐ手動で実行したい場合はこちら。
```bash
cd ~/premarket_alert
./run_update.sh
```
*(※ 100銘柄ずつ2秒間隔で取得するため、完了まで数分かかります。進行状況は画面には出ませんが `update.log` に出力されます。9:45 まで `caffeinate` が残るのでシェルはそこまで戻りません。すぐ戻したい場合は `/Users/msngkntr/.venv/bin/python update_watchlist.py` を直接実行してください)*

### 2. アラート通知の「通常テスト」
設定している実際の条件のまま、今の時間で判定させたい場合はこちら。
```bash
cd ~/premarket_alert
./run.sh
```
*(※ 条件を満たす強い銘柄がなければSlackには何も通知されません。実行結果は `alert.log` を確認してください)*

### 3. アラート通知の「強制テスト」
条件を満たす銘柄があるかどうかにかかわらず、必ずSlackへ通知を飛ばして連携を確認したい場合はこちら。
(※条件を -100% / RVOL 0倍 に緩め、時刻ガードも外して強制的に発火させます)
```bash
cd ~/premarket_alert
FORCE_RUN=1 MIN_CHANGE=-1 RVOL_THRESHOLD=0 CLOSE_TO_HIGH_THRESHOLD=1.0 ./run.sh
```
*(※ 東証が開いている平日 9:00〜15:30 以外に実行すると当日データがないため、銘柄は通知されず ⚠️ 付きのサマリーだけ届きます)*

### 4. ログファイルではなく、画面で結果を見ながら直接実行
`run.sh` を使うと結果が `alert.log` に保存されて画面には出ません。エラー文や取得状況をターミナルの画面で直接確認したい場合は、以下のように環境変数と仮想環境のPythonを指定して直接実行します。
```bash
cd ~/premarket_alert
set -a; source secrets.env; set +a
FORCE_RUN=1 /Users/msngkntr/.venv/bin/python premarket_alert.py
```
*(※ 9:40 以降に手動実行するときは `FORCE_RUN=1` を付けないと時刻ガードでスキップされます)*

### Macの自動起床時間の変更
現在は `07:55` に設定されています。変更したい場合は以下のコマンドを実行します。
```bash
sudo pmset repeat wakeorpoweron MTWRF 07:55:00
```
設定状況の確認: `pmset -g sched`

### 自動実行(launchd)の登録・解除
設定ファイルは `com.msngkntr.update_watchlist.plist` および `com.msngkntr.premarket_alert.plist` です。

**登録を解除して自動実行を止める:**
```bash
launchctl unload ~/Library/LaunchAgents/com.msngkntr.update_watchlist.plist
launchctl unload ~/Library/LaunchAgents/com.msngkntr.premarket_alert.plist
```

**再度登録する:**
```bash
launchctl load ~/Library/LaunchAgents/com.msngkntr.update_watchlist.plist
launchctl load ~/Library/LaunchAgents/com.msngkntr.premarket_alert.plist
```
*(※ `launchctl list | grep premarket` で登録状況を確認できます)*

- `backtest.py` : アラート条件を全営業日に機械的に当てはめるバックテスト
- `catalysts.csv` : 毎晩手で書く材料メモ(任意・`.gitignore` 済み)。書き方の例は `catalysts.example.csv`
- `run.sh` / `run_update.sh` : それぞれを実行するためのシェルスクリプト
- `secrets.env` : Slack Webhook URL が記載された機密ファイル
- `watchlist.txt` : 自動更新される監視対象の銘柄一覧
- `*.plist` : Macのlaunchdにスケジュールを登録するための設定ファイル
- `alert.log` / `update.log` : 実行結果のログファイル
